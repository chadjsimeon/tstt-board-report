================================================================================
  THE MASTER DATA FILE
================================================================================

All dashboard data (except AR Aging and the Consumer ARPU/usage files) comes
from ONE file:

    TSTT_Board_Data.xlsx   (in the project root folder)

It contains the following sheets. Each sheet name must be spelled EXACTLY
as shown — they are case-sensitive.

  Sheet Name          Page it feeds
  ─────────────────── ──────────────────────────────────────────────────────
  Financial_Monthly   Home + Financial Performance + Revenue Mix
  Cash_CAPEX          Cash, Working Capital & CAPEX
  Consumer_Sales      Consumer (Prepaid / Postpaid / WTTx)
  Business_Sales      Business Sales (Financial Performance tab)
  Pipeline            Business Sales (Pipeline tab)
  Renewals            Business Sales (Renewals at Risk tab)
  DPDI                DPDI
  AMPLIA_Financial    Amplia — Financial Performance
  Amplia_Commercial   Amplia — Commercial / Subscriber Metrics  ← NEW
  OPEX                OPEX & Cost Management
  EBITDA_Bridge       Financial Performance (waterfall chart)
  PnL_Breakdown       Financial Performance (P&L table / GP derivation)
  KPI_Summary         Home + Enterprise Scorecard
  PP_Plans            Consumer → Postpaid tab (Active Plans donut) ← OPTIONAL
  WTTx_Plans          Consumer → WTTx tab (Subscribers by Plan Type donut) ← OPTIONAL

MONTH FORMAT: All "Month" columns must use the format  Apr-26  (Mon-YY).
              Do NOT use full dates or different formats.


================================================================================
  ADDITIONAL SOURCE FILES (separate from TSTT_Board_Data.xlsx)
================================================================================

────────────────────────────────────────────────────────────────────────────────
A. PREPAID SUBS & REVENUE BY ARPU BUCKET
   File: Prepaid Subs and REV by ARPU buckets.xlsx
   Page: Consumer → Prepaid tab
────────────────────────────────────────────────────────────────────────────────
This is a separate file (NOT a sheet in TSTT_Board_Data.xlsx).
Sheet: "Export"

Structure:
- Row 0:  sub-header row (arpu_category / column labels)
- Rows 1–6:  data rows (one per ARPU bucket category)
- Row 7:  Total row (skipped by dashboard)
- Each ARPU bucket has a pair of columns: Subscribers | Revenue
- Column headers follow the pattern:  Jan-2025  Feb-2025  … (Mon-YYYY format)
  → The dashboard converts these to Mon-YY format automatically.

Required ARPU bucket category names (must match exactly):
  Very Low (0-5)
  Low (5-30)
  Medium (30-120)
  High (120-300)
  Very High (>300)

Revenue values must be in RAW TT$ — dashboard divides by 1,000,000.

To update for a new month:
  Add two new columns (Subscribers | Revenue) after the last existing pair.
  Use the header format  May-2026  (Mon-YYYY).

NOTE: This file also drives the subscriber movement card on the Prepaid tab.
The "Closing Base" for a month is the total Subscribers row in this file
(sum of all bucket categories for that month).

────────────────────────────────────────────────────────────────────────────────
B. PREPAID DATA USAGE
   File: dd_prepaid_data_usage_mth.xlsx
   Page: Consumer → Prepaid tab (Data Usage sub-section)
────────────────────────────────────────────────────────────────────────────────
Sheet: "Result 1"

Required columns:
  Column                 Format    Description
  ────────────────────── ───────── ────────────────────────────────────────────
  Month_Code             YYYYMM    e.g. 202601 for Jan 2026
  unique_data_users      Count     Distinct subscribers who used data
  bundle_users           Count     Subscribers who used a bundle
  payg_users             Count     Pay-as-you-go data users
  total_data_usage       MB        Total data consumed (megabytes)
  in_bundle_usage        MB        Data consumed within bundles
  payg_data_usage        MB        Data consumed as PAYG
  data_bundle_rev        Raw TT$   Revenue from data bundles
  payg_data_charges      Raw TT$   Revenue from PAYG data charges

Derived by dashboard:
  gb_per_user     = total_data_usage / unique_data_users / 1024
  bundle_pct      = bundle_users / unique_data_users × 100
  total_data_rev  = data_bundle_rev + payg_data_charges  (in TT$M)

To update: add new rows to the sheet with Month_Code in YYYYMM format.

────────────────────────────────────────────────────────────────────────────────
C. AR AGING / RECEIVABLES
   File: Receivables Executive Summary.xlsx
   Page: Cash, Working Capital & CAPEX
────────────────────────────────────────────────────────────────────────────────
Sheet: "Exec. Summary Receivables"

The AR aging data is loaded by utils/ar_loader.py. It uses a hardcoded
column index to select the reporting month. When a new reporting month is
available, update this constant in utils/ar_loader.py:

    APR_COL = 74   ← change this to the correct column index for the new month
                    (0-based: column A = 0, column B = 1, etc.)

If the file cannot be read, the dashboard falls back to hardcoded Apr-26
fallback values defined in the same file.

Row positions used (0-based):
  Rows 22–28  →  Fixed Enterprise Government aging buckets
  Rows 40–46  →  Mobile Enterprise Government aging buckets
  Rows  4–10  →  Total (all customers) aging buckets
  Government = rows 22–28 + rows 40–46
  Non-Government = Total minus Government

  Aging buckets:
    Row offset 0 → 0–30 days
    Row offset 1 → 31–60 days
    Row offset 2 → 61–90 days
    Row offset 3 → 91–180 days   (merged into 90–360 display)
    Row offset 4 → 181–360 days  (merged into 90–360 display)
    Row offset 5 → 360+ days

────────────────────────────────────────────────────────────────────────────────
D. BILLINGS
   File: billing (M).xlsx
   Page: Cash, Working Capital & CAPEX (Collections section)
────────────────────────────────────────────────────────────────────────────────
Sheet: "Sheet 1"

The dashboard computes Collections % as:
  this month's collections / prior month's billings

Structure:
  Column      Description
  ─────────── ──────────────────────────────────────────────────────────────
  LOB         Line of business — "Business Sales" or "Consumer Sales"
              (cell is merged/blank for sub-rows; dashboard uses ffill)
  Grouping    Sub-grouping — "Govt", "Non-Govt", or "Total"
  [months]    One column per month; header must be in Mon-YY format (Apr-26)
              Values are raw TT$ billing amounts

Required LOB / Grouping combinations used by the dashboard:
  Business Sales | Govt
  Business Sales | Non-Govt
  Consumer Sales | Total

To update: add a new column (header Mon-YY) with billing values for each row.

────────────────────────────────────────────────────────────────────────────────
E. COLLECTIONS
   File: collections (FULL).xlsx
   Page: Cash, Working Capital & CAPEX (Collections section)
────────────────────────────────────────────────────────────────────────────────
Sheet: "Sheet 1"

Identical structure to billing (M).xlsx above.
Values are raw TT$ collection amounts for each LOB/Grouping per month.

Required LOB / Grouping combinations:
  Business Sales | Govt
  Business Sales | Non-Govt
  Consumer Sales | Total

To update: add a new column (header Mon-YY) with collection values for each row.

NOTE: The three Collections_Pct columns in the Cash_CAPEX sheet
(Collections_Pct, Collections_Pct_Gov, Collections_Pct_NonGov) are no longer
used by the collections widget. The widget now reads billing (M).xlsx and
collections (FULL).xlsx directly. Leave those columns blank or at 0.


================================================================================
  ETL SCRIPTS
================================================================================

────────────────────────────────────────────────────────────────────────────────
build_board_data.py — MAIN ETL
────────────────────────────────────────────────────────────────────────────────
You do NOT need to run this manually every month unless the raw source data
format changes. The output (TSTT_Board_Data.xlsx) is committed to the repo
and is what the dashboard reads directly.

If you do need to rebuild TSTT_Board_Data.xlsx from source:

    python build_board_data.py

Source files the ETL reads:
  Consolidated Contribution Statements.xlsx  — raw P&L actuals (multi-sheet)
  subscriber_base_apw.xlsx                   — subscriber base by APW
  Amplia Metrics 2024-2025 February 2026.xlsx — Amplia KPI data
  OPEX_AOP_FY2027.xlsx                       — OPEX Annual Operating Plan FY2027

All source files must be in the project root folder.

────────────────────────────────────────────────────────────────────────────────
load_fy2027_opex.py — OPEX AOP LOADER (one-time / refresh only)
────────────────────────────────────────────────────────────────────────────────
Appends FY2027 OPEX plan rows (Apr-26 to Mar-27) into the OPEX sheet of
TSTT_Board_Data.xlsx without touching any other sheets.
Run this when OPEX_AOP_FY2027.xlsx is updated or replaced:

    python load_fy2027_opex.py

Requirements:
  - TSTT_Board_Data.xlsx must be CLOSED in Excel before running
  - OPEX_AOP_FY2027.xlsx must be in the project root folder
  - The script preserves any existing FY2027 actuals when re-running

================================================================================
  DATA RULES & COMMON MISTAKES
================================================================================

  DO:
    - Use Mon-YY format for ALL Month columns (e.g. Apr-26, May-26)
    - Enter all monetary values in RAW TT$ — the dashboard converts to TT$M
    - Enter percentages as DECIMALS in most sheets (0.28 not 28)
    - Enter ARPU / ARPU_AOP in Consumer_Sales as actual TT$ per subscriber
      (e.g. 350 for TT$350/month — this column is NOT divided by 1,000,000)
    - Keep sheet names exactly as listed — they are case-sensitive
    - Add new months as new ROWS (not new columns), except PnL_Breakdown
      which uses months as columns

  DO NOT:
    - Enter monetary values already in millions — the dashboard will
      divide again and show values 1,000,000x too small
    - Add PY columns (Revenue_PY, EBITDA_PY, etc.) — they are auto-derived
    - Add Variance or Variance_Pct to OPEX — auto-calculated
    - Add Churn_Pct to Consumer_Sales — auto-calculated
    - Rename or delete any sheet
